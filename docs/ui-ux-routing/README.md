# راهنمای جاری ارزیابی UI/UX و مسیریابی کلینیک آژی

پیاده‌سازی تیکت‌های۰۱ تا۰۹ و بررسی‌های خودکار این مرحله تکمیل‌اند. **پذیرش انسانی تا گزارش مشاهده‌های شما باز است.** بررسی واقعی مرورگر در این جلسه به‌دلیل رد صریح دسترسی localhost مسدود ماند؛ تلاش مجدد یا جایگزین انجام نشده است. راهنما و تست jsdom شاهد کیفیت بصری نیستند.

## اولین اقدام شما

در ریشهٔ پروژه `npm ci` (فقط در صورت نبود وابستگی‌ها) و سپس `npm run dev` را اجرا کنید. [خانه](http://localhost:5173/) را در یک تب تازه باز کنید. اگر حسابی فعال است «خروج از حساب» را بزنید. «ورود و رزرو نوبت» ← «حساب بیمار» ← «استفاده از مشخصات آزمایشی» ← تأیید رضایت ← «دریافت کد نمایشی» ← `123456` ← «تأیید و ورود». باید `/patient`، نام علی رضایی و نوبت‌های خودش را ببینید. برای خط مبنای مشترک، ابزار شناور «ابزارهای ارزیابی دمو» ← «ریست کارخانه‌ای داده‌ها» را با تأیید اجرا کنید؛ داده‌های مصنوعی ثبت‌شده پاک می‌شوند و حساب/مقصد حفظ می‌شوند.

اگر Vite پورت دیگری اعلام کرد، همان آدرس چاپ‌شده را برای ارزیابی دستی استفاده کنید. این دستور برای شماست؛ عامل در این جلسه مرورگر یا سرور تازه‌ای برای دورزدن محدودیت باز نکرده است.

## حساب‌ها، فایل‌ها و نقطهٔ شروع

همهٔ حساب‌ها و اطلاعات زیر ساختگی‌اند. موبایل `09123456789`، کد ملی معتبر نمایشی `1234567891` و OTP شش‌رقمی `123456` برای هر پنج انتخاب استفاده می‌شوند. ارقام فارسی/عربی هم پذیرفته می‌شوند. فرم حساب واقعی ایجاد نمی‌کند، پیامکی ارسال نمی‌شود و اطلاعات هویتی فرم ذخیره نمی‌شود. تغییر نقش فقط با خروج و ورود دوباره است؛ نوار قدیمی انتخاب نقش وجود ندارد.

| انتخاب در ورود | هویت | مقصدها |
| --- | --- | --- |
| حساب بیمار | علی رضایی | `/patient`، `/patient/booking`، `/patient/consultations/app-1` |
| حساب منشی تهران | مریم کریمی | `/secretary/tehran`، `/secretary/tehran/leaves` |
| حساب منشی اصفهان | نسیم صادقی | `/secretary/isfahan`، `/secretary/isfahan/leaves` |
| حساب پزشک | دکتر مریم احمدی | `/doctor`، `/doctor/shifts`، `/doctor/consultations/app-1` |
| حساب مدیر مالی | مهندس توکلی | `/finance`، `/finance/tariffs`، `/finance/shifts`، `/finance/settings` |

شناسهٔ URL با کد رهگیری فرق دارد: `app-1` همان `AGY-10142` است؛ `app-2` همان `AGY-10143` بیمار بدهکار مهدی سعیدی است. بیمار عادی نباید اتاق بیمار بدهکار را ببیند. نمونه‌های لغو `AGY-10188` و `AGY-10189` با زمان آیندهٔ پویا ساخته می‌شوند؛ برای تکرار پس از چند ساعت، رفرش و بازنشانی کنید.

برای رزرو، مدرک اختیاری است. در صورت نیاز یک PDF/PNG/JPG کاملاً ساختگی زیر۵MB با نام `test-cbc.pdf` یا `test-document.png` انتخاب کنید؛ فایل بالای۵MB باید خطا بدهد. تعرفه از خود صفحهٔ مالی دانلود می‌شود: `Clinic_Agy_Tariff_Template_v2.xlsx` با شیت‌های دقیق `Services_BaseInsurance` و `Supplementary_Rules`. روش ساخت فایل‌های `invalid.xlsx`، `unchanged.xlsx` و نمونه۲۰۰ردیفی در [تیکت۰۸](ticket-08.md) است؛ دادهٔ شخصی لازم نیست.

## مسیر یکپارچهٔ چندنقشی — همان نوبت را تا پایان دنبال کنید

این دور را از دادهٔ کارخانه و بدون اجرای تغییر تعرفه/لغو پیش از آن شروع کنید. کد نوبت تازه را یادداشت کنید؛ در مراحل بعد سراغ همان کد بروید، نه اولین ردیف فهرست.

1. **مهمان و بیمار:** خانه را ببینید، با حساب بیمار وارد شوید و «رزرو نوبت جدید» را بزنید. آنلاین ← دکتر مریم احمدی ← یک ساعت موجود ← بیمهٔ پیش‌فرض تأمین اجتماعی/دانا. تعرفه۲۸۰٬۰۰۰، پایه۸۴٬۰۰۰، تکمیلی۱۳۷٬۲۰۰، سهم بیمار۵۸٬۸۰۰ تومان است. از مدارک به پیش‌فاکتور و درگاه نمایشی بروید و «پرداخت موفق» را انتخاب کنید. تأیید قطعی و کد `AGY-…` بیاید. «مشاهده در نوبت‌های من» باید کارت همان نوبت را بدون هشدار کاذب باز کند.
2. **خروج و پذیرش:** خارج شوید و با حساب منشی تهران وارد شوید. کد تازه را در جستجو بزنید؛ اصلاح سهم بیمهٔ همان ردیف ← «ابطال بیمه تکمیلی (سهم۰)» ← ذخیره. سهم جدید بیمار۱۹۶٬۰۰۰ و بدهی۱۳۷٬۲۰۰ است؛ قفل نرم فعال می‌شود. صبر کنید دیالوگ موفقیت بسته شود.
3. **محدودیت بیمار:** خارج و با بیمار وارد شوید. همان کارت باید دلیل قفل و مبلغ بدهی، ورود مسدودِ غیرفعال و اقدام پرداخت مابه‌التفاوت داشته باشد. آدرس اتاق همان نوبت نیز نباید قفل را دور بزند.
4. **بازگشایی مجاز:** خارج و با منشی تهران وارد شوید؛ بازگشایی اضطراری همان کد را با دلیل ساختگی مانند «هماهنگی تلفنی برای ویزیت نمایشی» تأیید کنید. دوباره با بیمار، ورود همان کارت باید فعال باشد و URL اتاق با شناسهٔ همان نوبت باز شود. **بازگشایی بدهی را صفر نمی‌کند.** مسیر مستقل تسویه: داده‌ها را بازنشانی کنید، با بیمار ابزار دمو ← بیمار بدهکار ← پرداخت مابه‌التفاوت را بزنید؛ کیف پول به۰ و ورود فعال می‌رسد. پس از این آزمون مستقل، برای دور اصلی از ابتدا شروع کنید.
5. **پزشک:** از اتاق بیمار خارج از حساب شوید و با پزشک وارد شوید. کد تازه را جستجو و «شروع ویزیت تصویری» همان مورد را بزنید. URL اتاق باید شناسهٔ همان نوبت را داشته باشد. «درج نمونه یادداشت» را بزنید؛ مدارک و مشخصات مالی را ببینید و برگردید؛ پنج فیلد باقی بمانند. «ثبت نهایی و خاتمه ویزیت» ← دیالوگ موفقیت ← بازگشت به کارتابل، بدون هشدار کار ناتمام.
6. **خروجی مجاز بیمار و پذیرش:** با بیمار کارت همان کد باید نسخهٔ «کپسول مسکن روزی۱عدد، پرهیز از بی‌خوابی» و پیگیری «مراجعه مجدد۲هفته دیگر» را نشان دهد. شکایت «سردرد مزمن و احساس خستگی»، یافته «فشار خون13روی8» و تشخیص «میگرن ناشی از استرس» نباید دیده شوند. با منشی، جزئیات همان کد فقط پیگیری را از پرونده نشان دهد؛ نسخه و سه فیلد دیگر محرمانه بمانند. برای ادامهٔ آزمون‌های مستقل بازنشانی کنید.

نسخهٔ خودکار همین مسیر با رزرو **تازه** و همهٔ تغییر حساب‌ها از UI در [integratedRoleLifecycle.test.tsx](../../tests/browser/integratedRoleLifecycle.test.tsx) است. مدت اجرای ماشینی این مسیر، سنجش سرعت یا سهولت کار انسان نیست.

## شواهد، پوشش و حدود تحویل

شواهد هر برش بدون بازنویسی تاریخچه حفظ شده‌اند: [۰۱ خانه/ورود](ticket-01.md)، [۰۲ پوسته/مسیرها](ticket-02.md)، [۰۳ بیمار](ticket-03.md)، [۰۴ رزرو/guard](ticket-04.md)، [۰۵ پذیرش](ticket-05.md)، [۰۶ پزشک/اتاق](ticket-06.md)، [۰۷ گزارش](ticket-07.md)، [۰۸ عملیات مالی](ticket-08.md)، [۰۹ اتصال نهایی](ticket-09.md). محدودیت‌های موقت ابتدای هر برش با checkpointهای بعدی تکمیل شده‌اند؛ این README مرجع رفتار نهایی است. اسناد قدیمی [evaluation-guide](../evaluation-guide.md) و [ui-transformation](../ui-transformation-evaluation.md) سابقه‌اند و دستور نوار تغییر نقش آن‌ها جاری نیست.

برای تکرار پیش‌پرواز ماشینی:

```sh
npm test -- --reporter=dot
npm run build
git diff --check 0eaa111a36af2ca66eb91bf632386ff0bd3c9645...HEAD
git diff --check
```

پیش‌پرواز واقعی ۲۰۲۶-۱۱-۰۱ در مبنای یکپارچه `218c69a` به‌همراه تغییرات۰۹: **۲۴۰/۲۴۰ تست در۲۵فایل** موفق، مدت۱۱٫۴۶ثانیه؛ **build TypeScript/Vite موفق**، JS۱٬۰۲۸٫۵۰kB و gzip۳۰۵٫۸۰kB با هشدار موجود chunk بالای۵۰۰kB. هشدارهای قدیمی `act` در fixtureها باقی‌اند. working diff check و range check نسبت به `0eaa111a36af2ca66eb91bf632386ff0bd3c9645...HEAD` پس از commit موفق‌اند؛ EOF قدیمی در۰۹ اصلاح شد. وضعیت بازبینی مستقل در checkpoint۰۹ ثبت است. خودبازبینی منبع انجام شده؛ بازبینی مستقل دو محور توسط هماهنگ‌کننده پس از ادغام۰۹ انجام خواهد شد.

مرز آزمون جدید برنامهٔ کامل + Router است؛ fixture تنها آماده‌سازی داده/حساب را انجام می‌دهد. [ممیزی پوشش و شواهد نهایی تیکت۰۹](ticket-09.md) نتیجهٔ واقعی اجرا، مقادیر مستقل مالی و محل هر ماتریس را ثبت می‌کند. سوئیت قبلی `e2eEvaluationSuite` و assertionهای مالی/دامنه/محرمانگی آن حفظ‌اند؛ پنج assertion داخلی حساب/سناریو با حساب قابل مشاهده، URL و پیام جایگزین شدند.

مرورگر واقعی، چهار عرض، اندازه‌گیری کنتراست/لمس، صفحه‌کلید و focus/scroll واقعی، reduced motion و نمایش بومی beforeunload **مسدود/در انتظار** مانده‌اند؛ jsdom فقط رفتار و اتصال رویداد را اثبات می‌کند. تست خودکار و راهنمای آماده، پذیرش انسانی یا زمان رزرو توسط انسان را اثبات نمی‌کنند. برای هر مورد این قالب را گزارش کنید: **تیکت/ویژگی، حساب، URL، عرض، داده/فایل، اقدام، انتظار، مشاهده، نتیجه قبول/اشکال**. نخست همان دور بیمار تا پذیرش و پزشک را اجرا کنید و مشاهدهٔ هر مرحله را ثبت کنید.
