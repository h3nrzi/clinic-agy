# ارزیابی تیکت 03: پورتال بیمار

پیاده‌سازی و بررسی‌های خودکار انجام شده‌اند. مشاهدهٔ مرورگر واقعی و پذیرش انسانی **در انتظار گزارش کاربر** هستند.

## اولین اقدام شما

در پوشهٔ پروژه `npm run dev` را اجرا کنید و [پورتال بیمار](http://localhost:5173/patient) را باز کنید. با «حساب بیمار»، مشخصات آزمایشی، رضایت و کد `123456` وارد شوید. بالای صفحه باید «نوبت بعدی شما» با دکتر رضا حسینی و نوبت حضوری چهار ساعت آینده دیده شود؛ پس از آن کیف پول تسویه‌شده و چهار کارت نوبت دیده شوند. تاریخ نمونه‌های آینده هنگام بارگذاری ماژول seed ساخته می‌شود؛ برای ارزیابی مجدد پس از گذشت چند ساعت، صفحه را رفرش و از ابزارهای دمو بازنشانی کنید.

## دادهٔ حالت‌های خالی و طولانی

این داده‌ها فقط برای نمونهٔ محلی هستند. در صفحهٔ `/patient`، با بیمار عادی و پس از بازنشانی، در Console مرورگر قطعهٔ زیر را اجرا کنید. این قطعه از همان پایگاه دادهٔ ساختگی پروژه استفاده می‌کند و دادهٔ واقعی نمی‌خواهد:

```js
const { memoryDb } = await import('/src/mocks/db/memoryDb.ts');
const completed = memoryDb.getById('appointments', 'app-4');
memoryDb.update('appointments', 'app-future-urgent', {
  doctorName: 'پزشک'.repeat(70),
  serviceName: 'خدمت'.repeat(70),
});
memoryDb.update('appointments', completed.id, {
  clinicalNote: {
    ...completed.clinicalNote,
    prescriptions: 'نسخه آزمایشی بسیار طولانی '.repeat(40),
    mainComplaint: 'PRIVATE_COMPLAINT',
    findings: 'PRIVATE_FINDINGS',
    diagnosis: 'PRIVATE_DIAGNOSIS',
  },
});
```

نام و خدمت بدون فاصله، نسخهٔ بلند و چند کارت باید در چهار عرض۳۷۵/۷۶۸/۱۰۲۴/۱۴۴۰ داخل صفحه بمانند؛ متن‌های PRIVATE نباید دیده شوند. برای حالت خالی پس از همان import، قطعهٔ زیر را اجرا کنید:

```js
for (const app of [...memoryDb.getAll('appointments')]) {
  if (app.patientId === 'pat-1') memoryDb.delete('appointments', app.id);
}
```

باید «نوبت پیش رو ندارید» و «هنوز نوبتی ثبت نکرده‌اید» با اقدام شروع رزرو دیده شود؛ هیچ کارت بیمار دیگری ظاهر نشود. پس از بررسی، ابزارهای دمو ← بازنشانی تأییدشده را اجرا کنید. fixture همین حالت‌ها در `tests/browser/patientPortal.test.tsx` ثبت شده است؛ عبور jsdom شاهد اندازهٔ صفحه نیست.

## شواهد واقعی preflight — ۲۰۲۶-۱۱-۰۱

- مبنا `195390b` روی شاخهٔ `codex/ui-ux-03`؛ seam مصوب: برنامهٔ کامل + Router، با fixture واقعی و repositoryهای ساختگی موجود.
- چرخهٔ اول قرمز: region «نوبت بعدی شما» وجود نداشت. پس از ساخت سلسله‌مراتب و کارت‌های معنایی، تست۱/۱ سبز شد.
- چرخهٔ دوم قرمز: با باز بودن دیالوگ لغو، خروج از حساب همچنان در درخت قابل دسترسی بود. portal در `document.body` همراه hook موجود `useWorkspaceOverlay` آن را اصلاح کرد؛ تست۲/۲ سبز شد. گردش دوطرفهٔ Tab، Escape و بازگشت فوکوس در jsdom بررسی شدند.
- مجموعهٔ بیمار و لغو:۱۱/۱۱ موفق؛ افزون بر همهٔ assertionهای قبلی، نتایج مالی UI، محتوای خصوصی، متن طولانی، حذف نوبت لغوشده از خلاصه، تسویه، بازگشایی و حالت خالی پوشش داده شدند. دو انتخابگر ancestor/CSS در تست لغو و E2E به مقالهٔ نام‌دار تغییر کردند؛ assertionهای دامنه تضعیف نشدند.
- آخرین `npm test -- --reporter=dot`: **۱۷۹/۱۷۹ در۲۱ فایل موفق**، مدت۶٫۹۷ ثانیه. هشدارهای قدیمی `act` از fixtureهای مستقیم همچنان دیده می‌شوند؛ شکست وجود ندارد.
- `npm run build`: TypeScript و Vite موفق؛ JS۱٬۰۱۷٫۸۹kB، gzip۳۰۱٫۸۰kB. هشدار موجود chunk بالای۵۰۰kB باقی است.
- `git diff --check`: موفق. فایل‌های shell، stylesheet مشترک، repositories، قواعد لغو، رزرو و اتاق ویزیت تغییر نکردند.
- بازبینی منبع توسط پیاده‌ساز و والد انجام شد: فیلتر مالکیت، آینده/قطعی بودن خلاصه، شروط ONLINE/CONFIRMED/قفل ورود، کلید هویت، دو فیلد مجاز پرونده و فراخوانی‌های لغو/تسویه حفظ شدند. بازبینی والد، wrap نام بدون فاصله در خلاصه را درخواست کرد؛ روی مرز feature اصلاح و fixture طولانی افزوده شد. بررسی مستقل نهایی پروژه توسط والد هماهنگ می‌شود.
- تصمیم بصری از override پروژه و جستجوی UI/UX Pro Max دربارهٔ اندازه/فاصلهٔ هدف لمس و کارت موبایل گرفته شد: پنل سفید، توکن‌های مشترک رنگ/شعاع، متن خوانا، دکمه‌های حداقل۴۶px و فاصله۱۰px. مستندات جاری [React createPortal](https://react.dev/reference/react-dom/createPortal) از Context7 پس از resolve دریافت شد؛ portal با مدیریت فوکوس و غیرفعال‌سازی پس‌زمینه همراه است.
- **مرورگر واقعی اجرا نشد.** دسترسی localhost:5173 در همین جلسه صریحاً رد شده بود؛ هیچ تلاش مجدد یا جایگزین انجام نشد. مشاهدهٔ چهار عرض، کنتراست واقعی، اسکرول/هدف لمس، صفحه‌کلید بومی، کاهش حرکت و نمایش علامت مبلغ در RTL در انتظار هستند. قبولی خودکار و آماده‌بودن راهنما پذیرش انسانی نیست.
