## ۱. نقشهٔ اسناد معتبر فرانت‌اند

تمامی اسناد طراحی، معماری، تست و اجرای فرانت‌اند در این مسیر گردآوری شده‌اند و هیچ مرجع متعارضی خارج از این ساختار وجود ندارد:

1. **[سند مشخصات رفتار، جریان‌ها و سناریوهای پذیرش (`frontend-spec.md`)](./frontend-spec.md):**
   * تعریف نقش‌ها، مرزهای امنیتی و حدود صلاحیت.
   * کاتالوگ جریان‌های کاری (`FLOW-01` تا `FLOW-07`) با محوریت **جریان نماینده (رزرو آنلاین زیر ۳ دقیقه)**.
   * کاتالوگ صفحات (`SCREEN-01` تا `SCREEN-07`) و تعاملات کلیدی (`INT-01` تا `INT-08`).
   * ماتریس کنترل دسترسی فیلدهای شرح‌حال پزشکی (Field-Level RBAC).
   * سناریوهای پذیرش دقیق در ساختار Given-When-Then (`AC-01` تا `AC-08`).

2. **[معماری، استک فنی و ساختار ماژولار (`frontend-architecture.md`)](./frontend-architecture.md):**
   * توجیه انتخاب استک: React 19 + TypeScript + Vite + Tailwind CSS (RTL) + Zustand + PWA.
   * ساختار درختی دایرکتوری بر اساس دامنه‌های مستقل (Feature-Sliced).
   * مدل سه‌سطحی مالکیت State (Local Component, Global Client, Mock Repository Layer).
   * معماری شبیه‌سازها (درگاه پرداخت شاپرک، وب‌آرتی‌سی محلی، و نوار ابزار دمو با کلید تعویض نقش).

3. **[طرح جامع آزمون و اعتبارسنجی (`frontend-test-plan.md`)](./frontend-test-plan.md):**
   * هرم آزمون: تست‌های منطق مالی (Vitest Pure Logic) و تست‌های مرورگری (Playwright / Browser Runner).
   * ماتریس تست‌های منطق پرترکیب (`TEST-LOGIC-01` تا `TEST-LOGIC-10`): فرمول پلکانی بیمه، سهم پزشک، و لغو ۱۲ ساعته.
   * سوئیت تست‌های مرورگری: آزمون جریان نماینده، اصلاح بیمه توسط منشی، قفل نرم بدهکاری و اتاق ویزیت پزشک.
   * معیارهای پذیرش فنی و اعتبارسنجی شاخص زیر ۳ دقیقه.

4. **[برنامهٔ اجرایی و بسته‌های کاری (`frontend-execution-plan.md`)](./frontend-execution-plan.md):**
   * ساختار شکست کار (WBS) در قالب ۷ بستهٔ کاری پیوسته (`WP-00` تا `WP-06`).
   * ثبت تصمیم‌های مصوب فاز ۲ (DEC-FE-01 تا 03) و ماتریس آمادگی ۱۰۰٪ بسته‌های کاری (`WP-00` تا `WP-06`).

## ۲. راهنمای سشن تازه برای ورود به مرحلهٔ پیاده‌سازی

هر سشن تازه یا فرمان جدید می‌تواند بلافاصله از نقطهٔ زیر کار را ادامه دهد:

* **آخرین وضعیت اجرایی:**
  * بستهٔ کاری [`WP-00`](./frontend-execution-plan.md#بسته-کاری-wp-00-شالوده-محیط-شبیه-ساز-داده-و-نوار-ابزار-دمو) (راه‌اندازی پروژه، ریپازیتوری حافظه‌ای و نوار دمو) ✅ **تکمیل شد**.
  * بستهٔ کاری [`WP-01`](./frontend-execution-plan.md#بسته-کاری-wp-01-پیاده-سازی-موتورهای-منطق-خالص-و-تست-های-پایه) (موتورهای محاسباتی بیمه، سهم پزشک، لغو نوبت و تست‌های Vitest) ✅ **تکمیل شد**.
  * بستهٔ کاری [`WP-02`](./frontend-execution-plan.md#بسته-کاری-wp-02-جریان-نماینده--رزرو-نوبت-پرداخت-و-کیف-پول-flow-02) (جریان نماینده — رزرو نوبت زیر ۳ دقیقه، پیش‌فاکتور بیمه، شبیه‌ساز شاپرک و صدور کد نوبت قطعی) ✅ **تکمیل شد**.
  * بستهٔ کاری [`WP-03`](./frontend-execution-plan.md#بسته-کاری-wp-03-میز-کار-منشی-اصلاح-دستی-بیمه-و-قفل-نرم-بدهکاری-flow-03) (میز کار منشی، اصلاح دستی سهم بیمه، محاسبهٔ دلتا، قفل نرم بدهکاری و بازگشایی اضطراری) ✅ **تکمیل شد**.
  * بستهٔ کاری [`WP-04`](./frontend-execution-plan.md#بسته-کاری-wp-04-کارتابل-پزشک-اتاق-ویزیت-زنده-و-فرم-شرح-حال-۵-فیلدی-flow-04) (کارتابل پزشک، اتاق ویزیت تصویری زنده، فرم ۵ فیلدی شرح‌حال و تفکیک محرمانگی Field-Level RBAC) ✅ **تکمیل شد**.
  * بستهٔ کاری [`WP-05`](./frontend-execution-plan.md#بسته-کاری-wp-05-تقویم-شیفت-ها-مرخصی-و-ماژول-مالی-اکسل-۲-شیتی-flow-05-flow-06) (تقویم شیفت‌ها، لغو ۱۲ ساعته با کسر ۵۰٪ جریمه و ماژول مالی اکسل ۲ شیتی با جدول مقایسه‌ای Diff) ✅ **تکمیل شد**.
  * بستهٔ کاری [`WP-06`](./frontend-execution-plan.md#بسته-کاری-wp-06-آزمون-های-مرورگری-e2e-و-آماده-سازی-سشن-ارزیابی) (آزمون‌های مرورگری جامع E2E، پوشش FLOW-01 تا FLOW-06، اعتبارسنجی شاخص زیر ۳ دقیقه و تدوین راهنمای ارزیابی دموی انسانی) ✅ **تکمیل شد**.
* **وضعیت نهایی فاز ۲:** تمامی ۷ بستهٔ کاری (`WP-00` تا `WP-06`) با موفقیت ۱۰۰٪ پیاده‌سازی شدند و ۵۲ تست خودکار (تست‌های منطق خالص و مرورگری) سبز هستند.
* **راهنمای ارزیابی دموی تعاملی:** به سند [`evaluation-guide.md`](./evaluation-guide.md) مراجعه فرمایید.
* **مورد منتظر:** ارزیابی انسانی سناریوهای پنج‌گانهٔ دمو توسط کارفرما طبق راهنمای ارزیابی و اعلام بازخورد نهایی.
* **قاعدهٔ عدم دسترسی به زیرساخت واقعی:** هیچ کدی به اینترنت، دیتابیس، درگاه پرداخت یا پنل پیامک واقعی متصل نیست؛ تمامی تعاملات از طریق پکیج `mocks/` و شبیه‌سازهای داخلی تغذیه می‌شوند.
