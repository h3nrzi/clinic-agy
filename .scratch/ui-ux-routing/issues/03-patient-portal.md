# 03: بازطراحی پورتال بیمار

**What to build:** بیمار، به‌ویژه روی موبایل، نوبت‌ها، نسخه و دستور پیگیری و ماندهٔ کیف پول را سریع بفهمد و اقدامات فعلی لغو یا تسویه را با نتیجهٔ مالی و محدودیت ورود یکسان انجام دهد.

**Blocked by:** 02 — ناوبری یکپارچه و ابزارهای شناور دمو.

**Status:** resolved

- [x] نمای نوبت‌ها و پرونده با راهنمای UI/UX Pro Max و جهت بصری مصوب بازطراحی شود؛ بیمار mobile-first و کم‌تراکم‌تر از پنل‌های عملیاتی باشد.
- [x] نوبت بعدی معتبر، لیست نوبت‌ها، پزشک، زمان، نوع ویزیت، کد رهگیری و وضعیت هر نوبت با سلسله‌مراتب روشن و بدون برچسب صرفاً رنگی نمایش داده شوند؛ محاسبه یا وضعیت تازه ساخته نشود.
- [x] ماندهٔ کیف پول و معنای بدهی، بستانکاری یا تسویه روشن باشد؛ مبلغ و منبع داده همان رفتار موجود بماند.
- [x] بیمار فقط نسخه و دستور پیگیری مجاز را ببیند؛ شکایت، معاینه و تشخیص از طریق ظاهر یا مسیر نمایش داده نشوند.
- [x] لغو نوبت و دیالوگ تأیید با همان مرز زمانی، جریمه و بازگشت وجه فعلی کار کنند؛ قواعد جدید یا قابلیت جابه‌جایی تازه اضافه نشود.
- [x] قفل نرم، دلیل محدودیت، پرداخت مابه‌التفاوت و پیام بازگشایی اضطراری خوانا باشند و همان اثر فعلی را بر ورود بیمار داشته باشند.
- [x] مسیر شروع رزرو موجود روشن و قابل دسترس باشد؛ بازطراحی جریان رزرو در تیکت 04 و لینک مستقل اتاق در تیکت 06 انجام می‌شود و عملکرد موجود این دو ورودی در این تیکت نشکند.
- [x] حالت بدون نوبت، متن طولانی، فهرست چند نوبت و اقدامات هر نوبت در موبایل بدون سرریز کل صفحه قابل استفاده باشند.
- [x] کنترل‌ها برچسب و فوکوس واضح داشته باشند؛ دیالوگ لغو با صفحه‌کلید، Escape و بازگشت فوکوس درست کار کند. کنتراست، هدف لمس و کاهش حرکت رعایت شوند.
- [x] آزمون از سطح برنامه و Router، نمایش اطلاعات مجاز، لغو و اثر کیف پول، تسویه و قفل نرم را پوشش دهد؛ تست‌های موجود لغو و کیف پول بدون تضعیف حفظ شوند.
- [ ] build، تست مرتبط، بررسی کد و مشاهدهٔ مرورگری در چهار عرض مصوب انجام شوند؛ راهنمای ویژگی‌به‌ویژگی با دادهٔ آزمایشی، شواهد واقعی و اولین اقدام کاربر آماده شود و پذیرش انسانی باز بماند.

## Answer

پورتال بیمار با اولویت نوبت بعدی معتبر، معنای متنی مانده کیف پول، کارت‌های نام‌دار با جزئیات برچسب‌دار و اقدامات هر نوبت بازطراحی شد. نمایش پرونده فقط نسخه و دستور پیگیری است؛ مالکیت، کلید هویت، قواعد مالی/لغو، قفل نرم، تسویه و ورود موجود اتاق حفظ شدند. دیالوگ لغو portal، پس‌زمینه غیرفعال، فوکوس دوطرفه و اسکرول داخلی دارد. فایل‌های مشترک و منطق repository دست‌نخورده‌اند.

آزمون۱۷۹/۱۷۹، build و diff-check موفق‌اند؛ دو چرخه قرمز/سبز و بازبینی منبع ثبت شده‌اند. [راهنمای ویژگی‌به‌ویژگی و شواهد واقعی](../../../docs/ui-ux-routing/ticket-03.md) داده‌های حالت خالی/طولانی، اولین اقدام کاربر و ارزیابی مالی/حریم خصوصی را دارد. بررسی مرورگری چهار عرض طبق رد صریح دسترسی قبلی انجام نشد؛ checkbox ترکیبی build/مرورگر باز و پذیرش انسانی در انتظار مشاهده‌های کاربر باقی می‌ماند. والد بررسی مستقل نهایی را هماهنگ می‌کند.
