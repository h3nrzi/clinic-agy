# 05: بازطراحی میز پذیرش و بررسی مرخصی

**What to build:** منشی تهران و منشی اصفهان از میز پذیرش متراکم و خوانا، نوبت‌ها و مدارک را بررسی کنند، بیمه و بدهی را مطابق قواعد فعلی مدیریت کنند و درخواست‌های مرخصی را از مقصد مشخص خود بررسی کنند.

**Blocked by:** 02 — ناوبری یکپارچه و ابزارهای شناور دمو.

**Status:** resolved

- [x] پذیرش هر دو منشی با راهنمای UI/UX Pro Max و جهت بصری مصوب بازطراحی شود؛ تراکم مناسب دسکتاپ باشد و در موبایل نیز تمام اقدامات قابل استفاده بمانند.
- [x] جستجو، فیلترهای شعبه و وضعیت، تعدادها و وضعیت‌های نوبت خوانا باشند؛ دامنهٔ فعلی دسترسی، فیلتر و داده تغییر نکند و حساب دو منشی با یکدیگر اشتباه نشود.
- [x] فهرست و جزئیات نوبت، کشوی کناری، بازکردن مدارک و بزرگ‌نمایی از همان داده‌ها و جریان‌های فعلی استفاده کنند؛ حالت خالی و متن طولانی راهنمای روشن داشته باشند.
- [x] اصلاح سهم بیمه و نمایش مابه‌التفاوت، محدودیت زمانی اصلاح، اثر بدهی بر قفل نرم و تسویه، مطابق رفتار فعلی باقی بمانند.
- [x] بازگشایی اضطراری با دلیل و ثبت فعلی انجام شود؛ متن و نتیجهٔ اقدام روشن باشند و دسترسی تازه ایجاد نشود.
- [x] منشی از محتوای بالینی فقط دستور پیگیری مجاز را ببیند؛ بازطراحی کشو یا مدارک اطلاعات محرمانهٔ بیشتری نمایش ندهد.
- [x] مقصد مستقل درخواست‌های مرخصی، وضعیت‌های فعلی و اقدامات بررسی موجود را خوانا نمایش دهد؛ منطق تأیید یا رد تغییر نکند.
- [x] دیالوگ‌های تو‌در‌تو فقط لایهٔ بالایی را با Escape ببندند، فوکوس را محصور و پس از بستن به کنترل مناسب برگردانند؛ برچسب فرم‌ها و وضعیت کنترل‌ها قابل تشخیص باشند.
- [ ] کارت یا جدول موبایل عنوان هر مقدار را حفظ کند و کل صفحه سرریز افقی نداشته باشد؛ کنترل‌ها هدف لمس مناسب، کنتراست و فوکوس واضح داشته باشند و کاهش حرکت رعایت شود.
- [x] آزمون برنامهٔ کامل و Router برای هر دو حساب، جستجو/فیلتر، مدارک، اصلاح بیمه، قفل نرم، بازگشایی و مرخصی اجرا شود؛ assertionهای قبلی مالی و محرمانگی حفظ شوند.
- [ ] build، تست مرتبط، بررسی کد و ارزیابی مرورگری چهار عرض مصوب با صفحه‌کلید انجام شوند؛ راهنمای قابل تکرار هر اقدام، شواهد واقعی preflight و اولین اقدام کاربر آماده شوند و پذیرش انسانی باز بماند.

## Answer

میز پذیرش با تراکم عملیاتی، فیلترهای شعبهٔ موجود، جستجوی برچسب‌دار/تعداد/reset، وضعیت نوبت و ردیف‌های دارای عنوان در موبایل آماده شد. کشو، مدارک، سهم بیمه و بازگشایی هدف لمس و فوکوس واضح و فرم کوتاه‌ارتفاع اسکرول‌پذیر دارند. مقصد مرخصی کارت مستقل و نتیجهٔ بررسی دارد. عنوان نادرست فریز از UI حذف شد؛ هیچ محدودیت زمانی، فرمول یا دسترسی تازه اضافه نشده است. منشی فقط followUp را می‌بیند.

مالکیت scroll lock به useDialogFocus واگذار شد و تغییر تکراری useWorkspaceOverlay حذف شد؛ top-only Escape، Tab/Shift+Tab، containment و focus return با آزمون برنامهٔ کامل + Router بررسی شدند. API مشترک تغییر نکرد.

شواهد نهایی: ۱۷۷/۱۷۷ تست در۲۰ فایل، ۹/۹ مجموعهٔ پذیرش، build و diff-check موفق. assertionهای دامنهٔ قبلی حفظ شدند. بازبینی متمرکز هماهنگ‌کننده regression اسکرول را یافت و با چرخهٔ قرمز/سبز رفع شد؛ بررسی نهایی مستقل دو محور بعد از ادغام همهٔ تیکت‌ها انجام می‌شود.

راهنمای قابل تکرار و اولین اقدام: [docs/ui-ux-routing/ticket-05.md](../../../docs/ui-ux-routing/ticket-05.md). مرورگر واقعی چهار عرض و پذیرش انسانی در انتظار مشاهدهٔ کاربر باقی‌اند؛ localhost پیش‌تر رد شده و دوباره تلاش نشد. چک‌باکس‌های ارزیابی بصری به همین دلیل بازند.

پس از ادغام مبنای یکپارچه `83b9e59`، مجموعهٔ کامل **۱۸۵/۱۸۵ در۲۱ فایل** و build موفق شدند؛ جزئیات در راهنمای تیکت ثبت است.
